# 호두랑 — 화면·로딩·전환 스토리보드

2026-09-11 · v1 · 채택한 도트 호두를 바탕으로 한 앱 전체 설계

## 범위와 중심 경험

사용자가 작업을 고르면 호두가 자료를 찾고, 가져오고, 옆에서 함께 읽는다. 끝난 자료는 서재에 정리한다. 시작 화면의 포근한 분위기를 작업 화면에도 이어가되, 긴 글을 읽고 편집할 때는 본문과 도구가 중심이다.

**구현됨:** 시작 화면, 세 작업공간 진입, 작업공간에서 홈으로 복귀, 세션 안에서 논문 이어 읽기, 반응형 배치. 이어서 앱 전체 테마(`ui/hodu.css`), 공통 상태 컴포넌트(`ui/hodu.py`의 `loading`/`show_state`), 검색·가져오기·리더·서재·자소서 작업실의 로딩·빈 화면·오류 상태, 앱 전체 움직임 줄이기를 적용했다([앱 화면 검증 기록](withhodu-app-verification.md)). **후속:** 프레임별 스프라이트 애니메이션, 요청 ID 기반 비동기 페이지 전환, 오류 유형(네트워크·API 키·파일) 세분화, 검수 화면 미저장 변경 보호.

기준 자료: [캐릭터 설계 노트](hodu-pixel-design-notes.md), [도트 원본 시트](../../assets/hodu/hodu-pixel-reference-v1.png).

## 1. 공통 시각 언어

| 요소 | 설계 |
| --- | --- |
| 바탕 | 종이색 `#F8F5ED`, 본문·편집 영역은 밝은 `#FCFAF4` 또는 흰색 |
| 글자 | 짙은 올리브 브라운 `#39392E`, 보조 문구 `#747366` |
| 주요 동작 | 짙은 초록 `#3F5947`, 채워진 버튼은 한 영역에 하나 중심 |
| 경계 | `#E5DFD0` 1px, 둥근 모서리 12~16px, 그림자는 최소화 |
| 호두 | 채택된 그림의 황금색·크림색 유지. UI 강조색과 경쟁하지 않음 |
| 글꼴 | 운영체제 기본 한글 산세리프. 도트 글꼴은 긴 문장·버튼에 사용하지 않음 |
| 크기 | 데스크톱 홈 제목 48px, 모바일 34px, 작업 화면 제목 24~28px, 본문 15~17px |
| 배치 | 홈 최대 1120px. 작업 화면은 기존 넓은 읽기 영역을 활용 |
| 상태 | 아이콘·호두 포즈 + 정확한 설명 + 필요한 조치. 색상만으로 구분하지 않음 |

주인공이 호두여도 ‘검색’, ‘번역’, ‘저장’, ‘삭제’라는 기능 이름은 그대로 쓴다. 결과 건수·페이지 수·시간·최근 기록은 실제 데이터가 있을 때만 표시한다.

## 2. 장면별 화면 구성

### S00. 앱 시작 — 호두의 작은 읽기 작업실

- 진입: 새 세션 또는 사이드바의 ‘호두랑 시작 화면’.
- 상단: `호두랑 withHodu` 브랜드, ‘움직임 줄이기’ 토글.
- 본문 왼쪽: ‘오늘도, 호두랑 한 장씩.’ / ‘궁금한 논문을 찾고, 생각을 글로 정리해요. 호두가 곁에서 함께할게요.’
- 본문 오른쪽: 앉아 있는 호두, 작은 ‘같이 읽을까요?’ 말풍선, 바닥의 낮은 타원. 5초 중 짧은 구간에만 2px 움직이는 가벼운 환영 동작.
- 아래 세 입구: 논문 찾기(종이를 물어온 호두), 나의 서재(책 읽는 호두), 자기소개서 작업실(종이를 정리하는 호두).
- 세션에 펼쳐 둔 논문이 있으면 ‘이어서 읽기’ 행을 추가한다. 읽은 이력이 없는 사용자를 위해 가짜 기록을 표시하지 않는다.
- 모바일: 환영 문구 옆에 호두를 작게 배치하고 작업 입구 세 개를 세로로 둔다. 390×844 화면에서 첫 작업 버튼까지 보이도록 한다.
- 강제 대기·자동 넘어가기·재생 종료를 기다리는 버튼 잠금은 없다.

### S01. 논문 검색 — 호두에게 관심사 알려주기

- 상단에 ‘논문 검색’과 홈 복귀. 검색 입력창과 검색 버튼을 첫 시야에 둔다.
- 입력 전 호두는 입력 영역 옆에서 앉아 기다린다. 안내는 ‘어떤 연구가 궁금하세요?’.
- 검색어 예시는 placeholder에만 넣고 사용자 입력으로 제출하지 않는다.
- 옵션: 출처·결과 수·번역 모델은 사이드바에 유지한다.
- 빈 문자열 제출: 입력 바로 아래 ‘찾고 싶은 연구 주제를 입력해 주세요.’. 커서는 입력창에 유지한다.
- 제출 후 입력한 검색어를 그대로 보이고 S02 상태로 전환한다.

### S02. 논문을 찾는 중 — 킁킁 탐색

- 검색 결과가 생길 자리에 작은 상태 영역을 둔다. 호두의 SEARCH 루프는 64~96 CSS px.
- 제목 ‘호두가 논문을 찾고 있어요’, 보조 설명에는 실제 실행 중인 검색 출처를 표시한다.
- 진행률을 알 수 없는 동안 백분율·예상 결과 수를 만들지 않는다.
- 이전 결과가 있다면 읽을 수 있게 남기고 ‘새 결과를 찾는 중’으로 구분한다.
- 검색 버튼은 중복 요청을 막도록 비활성화. 현재 동기 호출에는 진짜 취소 기능이 없으므로 취소 버튼을 먼저 그리지 않는다.
- 성공 → S03. 빈 결과 → S04. 예외 → S14.

### S03. 검색 결과 — 호두가 찾은 논문들

- 헤더: 검색어, 실제 결과 수, 검색어 수정. 완료 인사는 작게 한 번만 재생한다.
- 논문 한 항목: 제목, 저자·연도·출처, 요약, ‘번역해서 보기’, ‘원문 링크’.
- 호두는 결과 항목마다 반복하지 않고 목록 상단에 한 마리만 둔다.
- 검색 주제 구체화 기능은 결과 위에 작은 보조 도구로 둔다. 결과 제목보다 더 크게 강조하지 않는다.
- 논문 선택 → S05. 재검색 → S02.

### S04. 검색 결과 없음 / 빈 서재

- 결과 없음: CURIOUS 포즈와 ‘찾은 논문이 없어요’, 원래 검색어 유지, ‘검색어 바꾸기’.
- 처음 방문한 서재: REST 또는 READ 정지 포즈, ‘첫 논문을 함께 모아볼까요?’, ‘논문 찾기’.
- 필터 적용 후 없음: 필터 유지, ‘이 조건에 맞는 논문이 없어요’, ‘필터 초기화’.
- 세 경우의 행동을 분리한다. 빈 서재를 오류로 표현하지 않는다.

### S05. 논문 가져오기 — 물어오기에서 책 펼치기까지

1. 원문 확보: FETCH 루프 + ‘호두가 논문을 가져오고 있어요’.
2. PDF 분석: 종이를 내려놓는 포즈 + ‘논문 페이지를 확인하고 있어요’.
3. 첫 페이지 번역: READ 루프 + ‘첫 페이지를 읽고 있어요’ 및 선택된 번역 엔진.
4. 준비 완료: 실제 원문과 번역을 즉시 표시. 완료 연출 때문에 리더 진입을 지연하지 않는다.

각 단계는 실제 함수 시작·완료에 연결한다. 실패하면 실패한 단계와 재시도 조치를 표시하며 이전 검색 결과로 돌아갈 수 있게 한다. API 키가 필요한 경우 설정 진입 경로를 함께 둔다.

### S06. 논문 리더 — 옆에서 같이 읽기

- 상단 얇은 도구막대: 뒤로, 논문 제목, 페이지, 보기 방식, 글자 설정, 질문.
- 중심: 원문·번역 두 열, 문단 대응 하이라이트. 읽기 화면에는 환영 문구를 반복하지 않는다.
- 호두는 도구막대 끝의 32px 정지 포즈. 본문을 가로질러 이동하지 않는다.
- 현재 페이지 번역 중에는 원문을 먼저 읽을 수 있고 번역 열에만 READ 상태를 둔다.
- 완료 시 번역 문단만 교체한다. 원문 스크롤·선택을 불필요하게 초기화하지 않는다.
- 모바일에서는 원문/번역을 전환하며 읽고, 버튼 터치 영역은 최소 44px를 목표로 한다.

### S07. 페이지 넘기기 — 한 장씩 따라가기

- 이미 캐시된 페이지: 즉시 표시하고 페이지 번호만 갱신. 불필요한 로딩 화면 없음.
- 새 페이지: 원문을 표시하고 번역 열에 ‘호두가 N페이지를 읽고 있어요’.
- 전환 시 본문 전체 슬라이드·페이지 뒤집기 효과는 사용하지 않는다. 후속 구현에서는 번역 영역에 120ms 이내의 짧은 나타남만 검토한다.
- 끝 페이지에서는 다음 버튼 비활성 및 ‘마지막 페이지’ 설명.
- 빠른 연속 입력은 최신 페이지 요청에 대응하고 이전 페이지 결과가 뒤늦게 화면을 덮지 않도록 요청 ID로 구분한다(후속 비동기 구현 시).

### S08. 논문 질문 / 근거 검색 — 호두와 짚어보기

- 질문 입력, 답변, 근거 문단을 같은 영역에 둔다.
- 처리 중: THINK 포즈와 ‘호두가 근거를 확인하고 있어요’.
- 답변 완료: 캐릭터 크기를 줄이고 답변과 출처를 읽기 쉽게 표시한다.
- 근거 없음: ‘자료에서 확인할 수 없어요’. 호두의 표정으로 답변 신뢰도를 대신하지 않는다.
- 자소서 검색에서는 내 경험과 참고 자료를 구분하는 기존 근거 규칙을 유지한다.

### S09. 나의 서재 — 모아 둔 종이 선반

- 컬렉션과 논문 목록은 기존 정보 구조를 유지한다. 상단에 정리하는 호두 한 마리.
- 논문 항목: 표지, 제목, 연도, 열람. 부가 메뉴에 이름 변경·이동·삭제.
- 정렬·검색·선택 상태를 명시한다. 선택된 항목 수와 비교분석 버튼을 같은 행에 배치한다.
- 저장·이동 중 ORGANIZE → 성공 시 DONE 1회. 파일 작업 실패 시 항목을 성공한 위치로 먼저 보내지 않는다.
- 비교분석: 두 묶음을 번갈아 보는 동작, 실제 분석 단계 또는 건수만 표시한다. 완료 시 보고서와 다운로드를 제공한다.
- 삭제는 문서명을 포함한 확인 뒤 실행한다. 호두가 종이를 버리는 장난스러운 연출을 넣지 않는다.

### S10. 자기소개서 작업실 — 내 글을 챙기는 자리

- 상단 탭: 보관함 / 자료 추가 / 전사 검수 / 근거 검색 / 문체 편집 / 설정·백업.
- 각 탭의 실제 작업명은 그대로 둔다. 호두의 말풍선은 첫 안내나 처리 상태에만 쓴다.
- 보관함은 문서 상태(대기·전사 중·검수 필요·승인)를 명확히 표시한다.
- 자료 추가 → S11, 검수 → S12, 문체 편집 → S13.

### S11. 업로드·전사 — 사진에서 글로

1. 파일 선택: 파일명·형식·크기 확인. 검증 오류는 파일별로 표시.
2. 저장: ORGANIZE + ‘호두가 자료를 챙기고 있어요’.
3. 전사: 사진과 종이를 번갈아 보는 포즈 + ‘사진 속 글을 옮기고 있어요’.
4. 완료: ‘글을 옮겼어요. 원본과 맞는지 확인해 주세요.’와 검수 진입.

실제 처리된 파일 수만 진행 정보로 표시한다. API 키가 없어 모의 전사로 실행되면 ‘모의 전사’라는 문구를 동작과 함께 계속 표시한다. 완료를 검수 승인으로 오해하게 하지 않는다.

### S12. 전사 검수 — 사용자가 마지막으로 확인

- 원본 사진과 편집 가능한 글을 나란히 배치. 회전·확대 도구는 사진 영역에 고정.
- 호두는 작은 정지 포즈. 사용자가 읽고 고칠 때 계속 움직이지 않는다.
- ‘수정 저장’과 ‘검수 승인’을 구분하고 승인한 문항만 검색 대상으로 유지한다.
- 저장 중 입력 내용 보존, 실패 시 재시도. 확인하지 않은 변경을 탭 전환으로 잃지 않게 한다(후속 상태 보호 구현).

### S13. 문체 편집 — 나답게 다듬기

- 초안 입력 → 문체 선택 → 수정안 생성 → 원문과 비교 → 새 버전 저장.
- 생성 중 READ/THINK 루프. ‘호두가 문장을 다듬고 있어요’.
- 비교 단계에서는 사실·수치 변경 확인 결과와 제안을 우선한다. 완료 포즈만으로 사실 보존을 보증하지 않는다.
- 사용자가 저장하기 전 원문을 덮어쓰지 않는다. 실패 시 초안을 유지한다.

### S14. 오류·복구 — 잠깐 멈춰도 괜찮아요

- 작게 귀를 낮춘 정지 호두 + 구체적 오류 문구 + 다시 시도 / 이전 화면.
- 네트워크 오류, API 키 누락, 파일 오류를 구분한다. 기술 진단은 펼칠 수 있는 상세 영역에 둔다.
- 처리 중 루프는 중단한다. 오류 후 성공 표정을 재생하지 않는다.
- 호두 그림 자체를 못 읽어도 실제 기능 버튼은 사용할 수 있게 한다.

### S15. 백업·내보내기 / 설정

- 백업 중 종이 묶음을 정리하는 호두와 실제 작업 상태. 성공 뒤 다운로드 버튼을 노출한다.
- 실패 시 다운로드 가능하다고 표시하지 않는다. 데이터 크기·문서 수는 실제 결과를 사용한다.
- 설정에서 API 키, 번역 엔진, 저장 위치, 움직임 줄이기를 명확히 구분한다.
- 키 입력·삭제 같은 중요한 조작에 캐릭터가 반응하더라도 완료 사실을 실제 상태로 확인한다.

## 3. 화면 사이 연결과 시간 규칙

| 출발 → 도착 | 계기 | 호두·전환 | 유지할 상태 |
| --- | --- | --- | --- |
| 시작 → 검색 | 논문 찾으러 가기 | 즉시 화면 변경, 이후 검색 제출 때 SEARCH | 기존 검색어·결과 |
| 시작 → 서재 | 서재 들어가기 | 즉시 변경, ORGANIZE 정지 포즈 | 컬렉션 선택 |
| 시작 → 자소서 | 글 정리하러 가기 | 즉시 변경 | 보관함·검수 자료 |
| 작업 → 시작 | 홈 버튼 | 환영 화면, 대기 연출 없음 | 세션의 현재 논문·페이지 |
| 시작 → 이어 읽기 | 이어서 읽기 | 리더 복원 | 논문·페이지·번역 캐시 |
| 검색 → 결과 | 요청 완료 | DONE 1회, 결과 즉시 사용 가능 | 검색어 |
| 결과 → 리더 | 논문 선택 | FETCH → READ → 리더 | 결과 목록 |
| 리더 → 다음 쪽 | 다음/페이지 선택 | 캐시 없음일 때만 READ | 보기 방식·읽기 설정 |
| 서재 → 비교 | 선택 후 비교 | 비교 루프 → 보고서 | 선택 항목 |
| 업로드 → 검수 | 전사 완료 후 사용자 선택 | DONE → 정지 | 원본·전사 초안 |
| 편집 → 저장 완료 | 실제 저장 성공 | DONE 1회 | 원문·새 버전 |
| 처리 중 → 오류 | 요청 실패 | 루프 즉시 중단 → 정지 | 입력·작업 대상 |

- 화면 진입은 강제 지연 없이 즉시 진행한다. 최초 자산 로딩에 별도 스플래시를 끼우지 않는다.
- 후속 상태 컴포넌트는 250ms 이하 작업에 로딩이 번쩍이지 않도록 지연 표시를 검토하되, 실제 완료는 지연하지 않는다.
- 성공 애니메이션 목표 600~800ms 1회, 오류는 정지 포즈. 모션 감소 시 모두 정지.
- 장기 처리만 반복 동작. 한 화면에서 반복하는 호두는 최대 한 마리.
- 상태 안내는 `role=status` / polite live region을 검토하며, 프레임마다 읽히는 텍스트를 변경하지 않는다.

## 4. 구현 구조와 자산 계획

현재 홈은 `ui/home.py`와 `ui/home.css`가 담당한다. 도트 원본 PNG를 CSS의 고정된 표시 영역으로 보여주므로 캐릭터를 다시 그리거나 원본을 변경하지 않는다. 홈의 2px 움직임은 CSS 연출이며 프레임별로 그린 스프라이트 애니메이션이 아니다.

표시할 때 CSS 명도·대비 필터와 multiply 합성을 적용해 기준표의 밝은 바탕이 페이지와 자연스럽게 이어지도록 했다. 실제 알파 투명 PNG는 아니므로 후속 자산 제작 시 필터 없이 사용할 수 있는 투명 파일로 교체한다. 작은 모바일 호두는 공간에 맞춰 축소하며, 런타임 전용 소형 도트 제작은 별도다.

후속 공통 컴포넌트는 `HoduStatus(state, message, detail, progress)` 형태로 시작한다. 상태 enum은 idle/search/fetch/read/organize/think/done/error/rest. 파일명·사용자 입력을 HTML에 넣을 때는 escape하고, 캐릭터 자산과 CSS는 로컬 파일을 사용한다.

| 제작 순서 | 실제 필요한 자산 | 적용 |
| --- | --- | --- |
| 1 | 투명 정면·FETCH·READ·ORGANIZE 정지 PNG | 현재 홈의 CSS 표시 영역을 교체 |
| 2 | SEARCH 6장, FETCH 8장, READ 6장 | 검색·다운로드·번역 상태 |
| 3 | DONE 6장, ERROR 정지, CURIOUS 정지 | 결과·실패·빈 화면 |
| 4 | ORGANIZE 6장, THINK 4장 | 서재·질문·전사·문체 편집 |
| 5 | 비교·사진 전사 전용 포즈 | 작업별 차이 보강 |

런타임 스프라이트 제작 전 픽셀 격자, 팔레트, 접지점, 알파를 정리한다. 기준표를 무조건 잘라 런타임 시트라고 부르지 않는다.

## 5. 상태별 구현 범위

| 상태 | 홈 v1 | 나머지 화면 개편 |
| --- | --- | --- |
| 기본·선택 | 세 작업 버튼과 기존 라우팅 연결 | 위 장면 설계에 따라 후속 |
| hover·focus | 버튼 배경 변화·명시적 초점 테두리 | 기존 스타일 유지 |
| loading·submitting | 홈은 네트워크 요청·저장 없이 이동 | 후속 공통 상태 컴포넌트 |
| empty | 기록이 없으면 이어 읽기 행 생략 | S04에 정의 |
| error | 이미지 누락 시 안내와 작업 버튼 유지 | S14에 정의 |
| disabled | 실행 가능한 세 입구를 불필요하게 막지 않음 | 처리 중 중복 제출 방지 설계 |
| success | 작업 진입·복귀; 가짜 성공 통계 없음 | 실제 작업 완료에만 DONE |
| 모션 감소 | OS 설정 + 홈 토글 적용 | 사이드바 토글·OS 설정을 앱 전체에 적용 |
