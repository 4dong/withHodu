## 현재 문제와 원인

- 원본 호두 아틀라스는 배경을 포함한 RGB 이미지다. `mix-blend-mode`와 밝기 필터로 배경을 숨겨 왔지만, Streamlit 재실행 중 opacity/합성 레이어가 바뀌는 순간과 사이드바에서 안정적으로 작동하지 않는다.
- 이전 정적 캡처만으로는 클릭 직후의 재발을 발견하지 못했다. 이번에는 재실행 중 상태도 검사한다.
- 입력/버튼/탭이 각각 다른 크기와 곡률을 사용하고, 작은 액션과 주요 CTA의 구분이 약하다.
- 초기 화면 상단이 모바일에서 잘리고, 장식과 CTA 사이의 간격이 불균일하다.
- 서재 헤더가 분할 컬럼 안에서 좁아지고 보고서 카드와 버튼이 분리되어 있다.
- `styles.py`의 오래된 스타일과 `hodu.css`, `home.css` 사이에 덮어쓰기가 중첩되어 있다. 공통 UI의 최종 규칙은 hodu.css, 시작 화면의 배치만 home.css가 소유하도록 정리한다.

## 디자인 방향: 따뜻하고 정교한 읽기 작업실

Apple과 Toss를 그대로 복제하지 않고, 명확한 제목·여백·우선순위가 있는 행동·안정된 표면이라는 설계 기준을 적용한다. 호두 픽셀 아트와 차분한 포레스트 그린을 브랜드 단서로 유지한다.

공개 참고: [Apple 대한민국](https://www.apple.com/kr/), [Toss](https://toss.im/) (2026-09-14 열람). 구체적인 치수와 색상은 이 앱을 위한 독자적 설계값이다.

### 공통 토큰

### 이미지 처리

원본은 유지하고 별도 투명 PNG를 추가한다. 테두리에서 연결되는 밝은 배경만 제거하며 호두 내부의 밝은 털, 책과 종이는 보존한다. 크기 1448×1086과 스프라이트 좌표는 그대로 유지한다. 실제 alpha 채널, 모든 포즈의 가장자리, 애니메이션 및 어두운 배경 합성을 검증한다. 성공 시 multiply·밝기 필터와 다중 합성 우회를 모두 제거한다. 이미지 데이터 캐시는 파일 변경을 식별해야 한다.

이전 생성 도구 결과는 RGB 체크무늬였으므로 제품에 사용하지 않는다. 로컬 픽셀 처리는 사용자 동의 후 완료했다.

### 화면별 적용

1. **시작 화면:** 상단 브랜드와 환경설정의 안정적인 높이, 여백이 있는 인트로, 같은 높이의 3개 진입 카드, 제목/설명/CTA의 기준선 정렬. 모바일에서는 장식과 글이 겹치지 않는 1열 구성.
2. **사이드바:** 브랜드 아래에 논문검색·나의서재·자소서 3개 버튼을 우선 배치. 홈 이동은 가벼운 보조 액션. 번역 설정과 환경설정은 접을 수 있는 보조 영역. 활성 메뉴와 포커스 명확히 구분.
3. **논문 검색:** 헤더와 하나의 명확한 검색 패널, 넉넉한 입력창과 검색 CTA. 결과 영역과 입력 영역의 간격 구분.
4. **나의 서재:** 전체 폭 헤더, 정렬된 도구 행, 컬렉션 카드와 액션 일체화, 별도 보고서 영역의 비중 축소. 실제 목록과 검색/정렬 기능 유지.
5. **자소서:** 긴 탭 이름이 잘리지 않도록 가로 스크롤, 자료 입력·보관함·검수·편집의 공통 컨트롤 규칙. 설명/단계 표시는 본문보다 낮은 대비.
6. **논문 리더:** 읽기 영역을 우선하며 도구 모음은 44px 제어, 원문/번역 경계와 곡률 통일.

## 검증 계획 (구현 전 확정)

- 자동: 기존 AppTest 라우팅/홈/자소서 테스트. 필요한 이미지 무결성 검증은 생성 산출물 자체에 대해 수행.
- 브라우저: 로컬 Chrome CDP로 1280px 데스크톱, 390px 모바일 캡처. 홈→서재→검색→자소서, 사이드바 열린 상태, 재실행 중 opacity 상태와 이미지, 포커스/호버/눌림 검사.
- 자료 보호: 생성/삭제/외부 AI 호출을 실제 데이터로 테스트하지 않는다. UI 검증용 별도 로컬 보관함 사용. 시각 샘플이 필요한 경우 검증용 자료임을 명시한다.
- 검증 증거: `scratch/ui-refinement-verification/`. 실행하지 못한 항목은 최종 기록에 이유를 명시한다.
- 완료 기준: 이미지 원본 보존, 실제 투명 alpha, 메뉴 정상 이동, 버튼/입력 높이, 모바일 가로 넘침 없음, 런타임 오류 없음, 클릭 중 흰 사각 배경 없음.

## 변경 범위와 되돌리기

UI와 이미지 표시만 수정한다. 사용자 데이터, API 키, 검색·번역·저장 기능의 구현은 변경하지 않는다. 작업 전부터 수정된 파일이 많으므로 git reset/checkout으로 되돌리지 않는다. 이번 작업 직전 주요 UI 파일 사본은 `scratch/ui-refinement-before/`에 저장했다. 필요하면 이번 변경 부분만 비교해 복원한다.
