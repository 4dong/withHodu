# 호두랑 작업 화면 — 구현·검증 기록

2026-09-11 · 로컬 Streamlit 앱 · [스토리보드](withhodu-screen-storyboard.md) S01~S15 적용분

## 구현 완료

- `ui/hodu.py`: 페이지 머리말, 섹션 안내, 상태 카드(`state_html`/`show_state`), 작업 중 표시(`loading`), 사이드바 브랜드, 움직임 줄이기 토글. 사용자 입력은 모두 escape하며 상태 카드는 `role=status`/`alert`를 사용한다.
- `ui/hodu.css`: 종이색·올리브·초록 팔레트를 기본 위젯(버튼·입력·탭·알림·확장 영역)에 적용, 호두 포즈 크롭, 640px 이하 배치, 모바일 버튼 최소 44px.
- `app.py`: 검색(S02)·가져오기(S05)·페이지 번역(S07) 로딩을 실제 함수 호출에 연결. 검색 실패 시 기존 결과 유지, 결과 없음/첫 방문 빈 화면 구분(S04), 리더 오류 시 다시 읽기·목록 복귀(S14). 다음 페이지 미리 번역은 현재 페이지 표시 뒤에 실행하고 실패해도 현재 페이지는 유지.
- `ui/components.py`: 리더 머리말과 도구막대(이전·페이지·다음을 가운데로 묶음), 보기 방식과 질문 버튼을 한 행에 배치, 질문 처리 중 THINK 상태(S06·S08).
- `ui/library_view.py`, `ui/essay/*`: 서재·비교분석·자소서 탭의 머리말, 빈 화면, 작업 중·완료·실패 상태(S09~S13, S15). 자소서 근거 검색 결과 키를 `essay_search_results`로 분리해 논문 검색 결과를 덮어쓰지 않음.

## Ran — 실제 실행한 검증

| 검증 | 결과 |
| --- | --- |
| `python3 -m unittest tests.test_hodu_home tests.test_hodu_ui tests.test_visual_highlighter` | 18개 통과 (로딩 표시가 예외 후 제거됨, escape·role, 자소서 검색이 논문 결과를 덮지 않음 포함) |
| 로컬 Chrome headless + CDP, 합성 데이터(`scratch/hodu_ui_fixture.py`) | 검색·서재·작업실·리더·상태 화면을 1440×1000 / 390×844에서 새로 열어 캡처. 가로 넘침 0, Streamlit 예외 0 |
| `git diff --check` | 공백 오류 없음 |

외부 검색·다운로드·번역·Gemini API는 호출하지 않았다. 로딩 표시는 AppTest와 상태 검증 화면으로만 확인했으며 실제 네트워크 지연 상황에서의 체감은 확인하지 않았다.

## 남은 한계

- 호두는 기준 시트를 CSS로 잘라 표시하며 투명 PNG·프레임 애니메이션이 아니다. THINK 포즈는 시트의 CURIOUS 얼굴 클로즈업을 사용한다.
- 동기 호출이므로 검색·번역 취소, 연속 페이지 입력의 요청 ID 구분은 없다.
- 오류 문구는 작업 단위로만 구분하며 네트워크·API 키·파일 오류를 따로 나누지 않는다.
- 스크린리더 실기, 전체 접근성 감사는 실행하지 않았다.
