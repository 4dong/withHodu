## 1. 목적과 산출물

호두가 자료를 찾아 물어오고, 곁에서 읽고, 정리해 주는 개인 작업 공간을 만든다. 모든 작업 상태에 같은 호두의 행동 언어를 쓰되, 논문 본문과 편집 화면은 읽기 편하게 유지한다.

- 한글 이름: **호두랑**, 영문 이름: **withHodu**. 영문 대소문자를 고정한다.
- 현재 `app.py`의 페이지 제목, `ui/sidebar.py`의 제목, README에는 이미 호두랑이 반영되어 있다.
- 기준 이미지: [호두 도트 레퍼런스 시트](../../assets/hodu/hodu-pixel-reference-v1.png).
- 재생성 프롬프트: [hodu-pixel-reference-prompt.txt](../../assets/hodu/hodu-pixel-reference-prompt.txt).
- 이번 산출물은 정적 캐릭터 기준표와 제작 노트다. 실제 GIF/APNG, 정렬된 스프라이트 시트 및 앱 전체 인터페이스 적용은 후속 제작 범위다.

## 3. 호두를 알아보게 하는 고정 규칙

1. **얼굴은 황금빛 주황, 눈썹·주둥이는 밝은 크림색.** 눈 위의 밝은 부분을 작은 두 덩어리로 남긴다. 얼굴 전체를 흰 마스크로 덮지 않는다.
2. **검고 둥근 두 눈과 짧게 돌출된 주둥이.** 기본 표정에서도 눈을 점 하나로 축소하지 않는다. 눈 하이라이트는 한쪽당 최대 1 논리 픽셀을 기준으로 한다.
3. **작게 솟은 삼각 귀와 넓은 볼 털.** 귀가 길어져 여우처럼 보이거나 둥근 곰 귀로 바뀌지 않게 한다.
4. **작은 몸통과 짧은 네 다리, 등에 말린 풍성한 꼬리.** 꼬리를 가느다란 막대나 아래로 처진 형태로 바꾸지 않는다.
5. **밝은 가슴과 발끝.** 주황 머리와 크림빛 몸통을 구분한다. 과장된 흰 양말 무늬를 추가하지 않는다.
6. 웃을 때만 작은 분홍 혀를 보인다. 기본 의상·목걸이·안경은 없다. 종이와 책은 작업 중에만 등장한다.

## 4. 도트 규격과 팔레트

아래 수치와 HEX는 사진의 정밀 측색 결과가 아니라 후속 픽셀 작업을 위한 제안값이다. 생성 기준표의 실제 색 수나 격자가 이 규격과 정확히 일치한다고 간주하지 않는다.

| 항목 | 제작 규격 |
| --- | --- |
| 기본 전신 | 64×64 논리 픽셀, 투명 배경, 외곽 안전 여백 최소 4px |
| 소품 포함 작업 동작 | 96×64 논리 픽셀, 소품도 동일 픽셀 크기 |
| 작은 아이콘 | 24×24 또는 32×32 별도 리드로잉; 전신을 자동 축소하지 않음 |
| 확대 | 2·3·4배 정수 확대, nearest-neighbor, 웹에서는 `image-rendering: pixelated` |
| 윤곽 | 짙은 갈색 1px 중심, 털 끝은 2~3px 덩어리, 긴 톱니·고립 픽셀 억제 |
| 명암 | 부위당 2~3단계, 평면 색 덩어리; 그라데이션·블러·반투명 가장자리 금지 |
| 기준점 | 64×64 기준 발바닥 접지점 (32, 58); 프레임 사이 캔버스와 기준점 고정 |
| 비율 | 정면 앉기에서 머리·볼 너비 약 32~36px, 몸통 약 24~28px를 시작점으로 조정 |

| 실제 기능·화면 | 호두의 행동 | 상태 문구 예시 | 적용 지점 |
| --- | --- | --- | --- |
| 홈·사이드바 | 앉아서 가끔 눈을 깜박임 | 호두랑 · 함께 읽고 정리해요 | `ui/sidebar.py`, `app.py` |
| 논문 검색 | 코를 낮춰 종이 주변을 킁킁 탐색 | 호두가 논문을 찾고 있어요 | `app.py` 검색 흐름 |
| 논문 다운로드·열기 | 종이 한 장을 물고 짧게 걸어옴 | 호두가 논문을 가져오고 있어요 | `process_paper_and_load` |
| 페이지 번역 | 펼친 책을 보며 고개를 좌우로 조금 움직임 | 호두가 이 페이지를 읽고 있어요 | `app.py` 번역 로딩 카드 |
| 질문·근거 검색 | 책 위에 앞발을 얹고 고개를 갸웃 | 호두가 근거를 확인하고 있어요 | `ui/components.py`, `ui/essay/search_view.py` |

| 문체 편집 | 종이 옆에서 고개를 끄덕임 | 호두가 문장을 다듬고 있어요 | `ui/essay/style_view.py` |
| 백업·내보내기 | 정리한 종이 묶음을 옆으로 밀어 줌 | 호두가 자료를 챙기고 있어요 | `ui/essay/workspace.py` |

| 빈 검색 결과 | 멈춰 앉아서 고개를 갸웃 | 찾은 자료가 없어요. 검색어를 바꿔 보세요 | 검색·서재 빈 화면 |

| 유휴·휴식 | 앞발에 머리를 놓고 잠듦 | 필요할 때 불러 주세요 | 홈의 유휴 상태 |

문구는 친근하게 쓰되 검색·저장·삭제·번역 같은 버튼 이름은 기능을 그대로 드러낸다. 모의 전사, 실제 진행 건수, 실패 원인, 사용자 확인이 필요한 상태는 캐릭터 대사와 별도로 정확히 표시한다. 삭제 성공을 미리 연기하거나 실제 처리율을 달리는 거리로 추정하지 않는다.

## 6. 애니메이션 제작표

| ID | 프레임·타이밍 초안 | 동작 설계 | 반복 |
| --- | --- | --- | --- |
| `idle` | 4장, 1800/100/120/1800ms | 정면 → 반쯤 감기 → 감기 → 정면 | 유휴 시 |
| `search` | 6장, 각 140ms | 코 내리기 → 좌우 탐색 → 복귀 | 작업 중 |
| `fetch` | 8장, 각 110ms | 네 발 교차 걷기, 종이와 꼬리는 몸에 연결 | 다운로드 중 |
| `read` | 6장, 각 180ms | 책 보기 → 작은 고개 이동 → 눈 깜박임 | 번역 중 |
| `organize` | 6장, 각 150ms | 앞발 들기 → 종이에 닿기 → 정렬 → 원위치 | 저장 중 |
| `think` | 4장, 각 300ms | 정면 → 약한 갸웃 → 유지 → 복귀 | 근거 확인 중 |
| `done` | 6장, 각 120ms | 앞발 인사와 꼬리 흔들기 → 기본 자세 | 1회 |
| `rest` | 4장, 각 700ms | 감은 눈 고정, 몸통 높이만 1px 변화 | 홈 유휴 시 |
| `error` | 2장, 200/1000ms | 귀를 조금 낮추고 정지 | 1회 후 정지 |

걷기는 단순 이미지 좌우 이동 대신 발 접지·들림을 그린다. 몸통 상하 이동은 1px부터 시작하며 머리 크기, 눈 간격, 주둥이 색 경계가 프레임마다 흔들리지 않게 한다. 꼬리는 뿌리를 고정하고 끝부분만 움직인다. 논문을 물 때 종이가 코와 눈을 가리지 않게 한다.

루프의 마지막에서 첫 프레임으로 되돌아갈 때 발·책·종이가 튀지 않아야 한다. 성공·실패·취소 시 작업 루프를 즉시 중단하고 결과 상태로 전환한다. 짧은 작업에 애니메이션을 끝까지 보여 주려고 완료를 지연하지 않는다.

## 7. 화면 전체에 적용하는 원칙

- 동시에 움직이는 주 캐릭터는 한 마리만 둔다. 처리 중인 영역 가까이 배치해 호두가 무엇을 돕는지 연결한다.
- 본문 위를 걸어다니거나 버튼을 가리지 않는다. 리더에서는 여백 또는 상태 카드에 작게 배치한다.
- 작업이 없을 때는 긴 정지 구간을 둔다. 중요한 읽기·입력 화면에서는 기본 정지 이미지를 우선한다.
- 움직임 줄이기 설정에서는 동일 상태의 정적 포즈를 사용한다. 캐릭터 없이도 상태 문구와 진행 정보를 이해할 수 있어야 한다.
- 실패를 슬픈 연출만으로 알리지 않는다. 오류 이유와 재시도 수단을 함께 제공한다.
- 새로운 테마 적용 시 기존 로딩 점·회전 아이콘과 호두 동작이 겹치지 않게 공통 상태 컴포넌트로 통합한다.

## 8. 후속 제작 파일 계약과 검수

권장 파일 구조는 `assets/hodu/sprites/hodu-{state}-{size}.png`와 `assets/hodu/animations/hodu-{state}.apng`다. 웹 앱은 투명 PNG 시트와 프레임 메타데이터를 우선 검토하고, GIF는 공유용 미리보기로 사용한다. 메타데이터에는 `frameWidth`, `frameHeight`, `frameCount`, `durationsMs`, `anchor`, `loop`를 기록한다.

생성 이미지의 포즈들은 **컨셉 기준**이다. 그대로 잘라 쓰는 것만으로 64px 격자·팔레트·접지 정렬이 맞는 런타임 스프라이트가 되지는 않는다. 후속 제작에서 기준 격자에 맞춰 정리하고 실제 프레임을 그려야 한다.

검수 순서:

1. 기본 정면을 실제 사진과 비교해 밝은 눈썹, 크림 주둥이, 작은 귀, 볼 털을 확인한다.
2. 전신 포즈에서 꼬리가 등에 말리고 네 발 구조가 자연스러운지 확인한다.
3. 1배율과 3배율로 확인해 도트 크기·색 구획·실루엣을 정리한다.
4. 양 끝 프레임을 겹쳐 접지점·눈·코·몸통 크기 변화가 의도된 것인지 확인한다.
5. 밝은 배경·어두운 배경에서 알파 가장자리와 소품 가독성을 확인한다.
6. 실제 처리 시작·성공·실패·취소와 애니메이션 전환을 연결해 확인한다.
7. 움직임 줄이기 모드 및 정지 상태에서도 기능과 상태를 읽을 수 있는지 확인한다.

제작 우선순위는 기본 정면 → `idle` → `search` → `fetch` → `read` → `done` → `error` → 나머지 동작 순이다.

## 9. v1 생성 결과 검토

내장 `image_gen`으로 1448×1086 PNG 기준표를 생성했다. 정면·사선·측면·후면과 표정 및 작업 포즈 12칸을 확인했으며, 밝은 눈썹과 주둥이, 검은 눈·코, 등 위의 크림색 꼬리가 유지된다. 사진보다 볼과 몸통을 둥글게 단순화한 캐릭터다.

후속 픽셀 정리에서는 현재의 세밀한 털 명암을 더 큰 색 덩어리로 줄이고, 사진의 비교적 밝은 몸통을 좀 더 반영한다. 기본 정면은 현재 웃는 포즈와 별개로 입을 다문 중립 포즈도 그린다. 이 PNG는 아이보리 배경이 포함된 정적 참고 이미지이며 투명 스프라이트나 움직이는 파일은 아니다.
